# Changelog

Loopora is still experimental local-first software. This changelog is the public history entry for user-visible changes, adoption-risk notes, and release evidence. It is not a support promise, license grant, or substitute for [SECURITY.md](./SECURITY.md).

## Unreleased

This repository does not yet publish a supported release tag in this changelog. Until maintainers create one, public adopters should treat source checkout changes as experimental and verify the current development line before relying on behavior.

Current unreleased work should be summarized here when it changes user-visible behavior, public contracts, setup/readiness routes, package contents, support/security routing, compatibility risk, or release/distribution posture.

### Unreleased Changes

- Agent Native submit handoffs now carry an explicit host role-dispatch attestation. Newly generated commands include `--attest-role-dispatch`; successful submit summaries and Core events distinguish that source from legacy template auto-repair, reject arbitrary source labels, and keep both attestation sources separate from native trace and task proof. Complete result wrappers and the legacy implicit repair path remain compatible during migration.
- Agent Native first-run handoff now distinguishes a Core-prepared step from host-dispatched role work. Compact and plain work panels name the exact target agent, current-host handoff ownership, evidence focus, and bounded top gaps; plain output removes repeated static todo and duplicate Run URL blocks while preserving complete copyable recovery commands.
- Agent Native candidate `READY` now keeps the original confirmed task anchor visible beside the candidate task scope and judgments. Core readiness explicitly means candidate-contract validity rather than automatic task match, so the same Agent must repair a mismatch before `/loopora-run`.
- Demo now separates zero-configuration evaluation into a completed evidence sample and an initially empty creation playground. CLI and the persistent Web disclosure link both paths, while Demo Fit/Compose navigation stays pinned to the playground so sample artifacts cannot force first-time creators into existing-work recovery. A process-wide resolved-path scope now rejects external and symlink-escaped workdirs before project state can be read or written; Web removes arbitrary project switching and locks composition targets to the playground. CLI and Web provide a real-task `start --workdir "$PWD"` handoff that preserves source-checkout entry and language without carrying the temporary App home. Both projects remain under one temporary App lifecycle. `loopora demo --language zh` keeps terminal lifecycle text, compiler-generated checks, coverage labels/reasons, simulated role evidence and handoffs, and the final task verdict in Chinese; stable identifiers remain language-neutral, and Web chrome continues to negotiate its own browser locale.
- Start and Fit now preserve one executable command context across compact, detailed, JSON, and Web Fit Guide views. Generated Web, review, same-Agent setup, Doctor, and Support commands retain a resolved custom `LOOPORA_HOME`, shell-quote paths with spaces, and keep normalized terminal language. Same-Agent setup exposes `init current` only for one detected host; unavailable/ambiguous detection exposes explicit Codex/Claude/OpenCode choices instead. Structured actions distinguish primary-command readiness from an actionable fallback choice, and never include host session/thread values.
- Recovery create/inspect/restore now expose versioned structured summaries with the same purpose choices, ordered next actions, and readiness dependencies as terminal output. Inspect makes its three no-write paths explicitly mutually exclusive; restore distinguishes preview, blocked, complete, and no-restore-needed states. An all-identical archive no longer looks like a pending restore or offers a destructive `--yes` action.
- Chinese first use now reaches the final Web-start boundary without dropping language. `loopora serve` accepts canonical `en`/`zh` plus locale aliases; startup, existing-service reuse, target-directory, port/bind, network-auth, and App-state recovery render as one plain language, and Doctor/Fit/Start/same-Agent commands retain `--language zh`. Serve JSON and browser URLs remain language-neutral; Web page locale still follows the browser's `Accept-Language` instead of a CLI override.
- Archive-first App recovery now remains an understandable, closed safety journey. Recovery create/inspect/restore and development reset accept canonical `en`/`zh` plus locale aliases, retain the language in generated Status/Doctor/archive/reset/restore commands, and keep JSON semantics neutral. After inspection, users explicitly choose a no-write App reset preview, exact-path restore preview only for missing files, or Doctor. Restore now compares the live App database through a consistent SQLite snapshot, so unchanged WAL/page layout no longer creates a false conflict while real logical changes still fail closed.
- Chinese first use now stays in one terminal language from task review through same-Agent setup. `loopora init current`, explicit `init <agent>`, and their check/recovery paths accept canonical `en`/`zh` plus locale aliases; Doctor and Fit setup commands retain normalized `--language zh`. Plain setup output localizes as one flow while install/readiness JSON schemas, status ids, and command fields remain language-neutral.
- Doctor now supports complete Chinese terminal guidance through `--language zh` on both root and diagnostics-group commands. Locale aliases normalize to canonical `zh`, source-checkout reruns and Doctor/Fit/Support follow-ups retain the language, and recovery, Web, Agent-entry, next-action, and first-task sections localize together. Private/public JSON schemas and action kinds remain language-neutral.
- Doctor now presents a risk-ordered recovery frontier instead of a flat first-use checklist. Incompatible App state makes the private recovery archive the primary action before reset/Web/setup, while healthy first use still leads with fit; return/refresh actions are deferred until a concrete Agent entry is ready. Plain, private JSON, and redacted public JSON expose the same primary action kind.
- `loopora status` is now genuinely storage-read-only by default. Service construction no longer reconciles stale Runs, orphaned planning sessions, or projection backfills merely because a user inspected existing work; instead status reports dead-worker candidates and offers an explicit, project-scoped `--reconcile` action. Reconciliation retains the existing stopped/interrupted recovery semantics, skips non-cancelled live workers, and touches other projects only when the user explicitly selects `--all`.
- Incompatible local App state now follows one archive-first recovery path across command errors, development-reset preview, Doctor, Start/Fit, Serve, and Web Tools. Each surface offers a private exact-path recovery archive before reset preview, structured reset actions depend on archive success, and an older incompatible SQLite schema can be archived and inspected without opening it as current App state. Reset remains no-write by default and still requires explicit `--yes` after scope review.
- Existing work now has one project-level return point. `loopora status --workdir <project>` reuses the Web workbench's attention order to combine interrupted or active planning, recoverable Runs, evidence gaps, recent results, and saved unrun Loops into one read-only next action; `--all` is the explicit cross-project scope and `--json` returns the complete compact projection.
- Web planning sessions now recover after a local service crash or restart instead of remaining permanently Active. Startup and reads preserve live provider work, reconcile dead local workers into an explicit Interrupted state, retain the task/transcript/working agreement/candidate file, and offer Resume planning through the existing retry boundary. A cancellation recorded before the crash resolves as Stopped rather than Interrupted, and Home/history no longer describe orphaned sessions as still composing.
- Local state now has an explicit private recovery path. `loopora recovery create` snapshots the SQLite App catalog plus one project's managed Loop, Run, evidence, and planning state; `inspect` verifies a versioned checksum manifest and SQLite integrity; `restore` is no-write by default, requires exact source paths and `--yes`, keeps identical files, and refuses changed targets. Archives exclude project source, logs, Agent entries/inbox files, credentials, and unknown `.loopora` directories, but include private prompts, transcripts, raw model output, evidence, settings, and absolute paths, so they are never public support bundles.
- Stopping a Web planning conversation is now a closed, resumable user action instead of a visible execution failure. Provider exit-code races preserve cancellation intent across Codex, Claude, OpenCode, and custom commands; APIs keep the raw compatibility status while projecting `status_label=cancelled`, and desktop/mobile history plus recovery surfaces consistently show a neutral stopped state.
- Local source installation now separates adopter and contributor lifecycles. Ordinary users install an isolated wheel-backed copy with `uv tool install .`, so source edits do not silently change the active CLI; contributors may explicitly choose editable installation. Wheel and sdist artifacts retain the matching build-time Git revision plus clean/dirty state without checkout paths, and the default package-build gate verifies that provenance before launching `loopora --version` from the wheel in an isolated offline environment.
- Fit Guide now opens on the actual task decision instead of an explanatory hero and nested disclosures. The task and direct-path stop are visible in the first viewport, remaining judgment appears progressively, and partial reviews with a task can continue straight into Web conversation for clarification; Same-Agent setup and copyable `/loopora-plan` handoff still require the complete reviewed judgment.
- Same-Agent Setup now opens on the actual setup workbench instead of a route-choice hero. Target project and current Codex/Claude Code/OpenCode host share the first viewport before readiness or mutation controls, while alternate Web/Fit/Support paths follow the setup. Recent targets remain in the global project switcher and input suggestions instead of a second button list, and switching project from this safe setup page refreshes in place; untrusted or deep return targets still fall back to Home.
- The Web shell now treats target project as a controllable scope instead of a passive path label. Users can switch among all projects, usable recent projects, an absolute path, or a native folder choice; every switch validates the resolved directory and only ready targets enter recents. Deep work returns Home while safe setup may refresh in place. Explicit all-project scope can override a `serve --workdir` startup default without overriding a Loop/Run/Plan's own project, and an active Web conversation blocks scope changes until stopped.
- Saved Plan File detail now preserves READY's judgment-first model instead of reverting to an action-heavy source editor. Success, fake-done risk, required evidence, next-Run direction, and closure precede the Run decision; accessible Run-flow and full-contract views keep execution boundaries inspectable, while editing, reusable assets, YAML exchange, and deletion move into deferred management. Web-owned Plans retain their Run route, same-Agent Plans remain host-owned, incomplete judgment leads with improvement while keeping legacy Run access secondary, and no-JS renders every review view sequentially.
- A recorded passing Loop with open advisory targets now stays visibly closed: the frozen required-target basis owns the decision surface, while optional follow-up lives beside that evidence as a secondary action instead of reopening the Hero with a default-work CTA. Ordinary first/new Runs, recovery/evidence continuation, and same-Agent handoff keep their existing primary paths.
- Terminal Run detail now makes evidence own the next decision. Record, rerun, improve, advisory-follow-up, and reopen actions appear once after the evidence outcome instead of competing in the hero and key-takeaway card; unresolved results lead with improvement/next evidence while recording remains a reversible attention state, not proof. Hero keeps navigation, active Stop, and same-Agent handoff, while Loop/private-evidence exports share one secondary menu. Mobile key takeaways enter the first viewport substantially earlier.
- READY review is now a decision-first surface instead of a multi-thousand-pixel contract tail. It lands deterministically at the review boundary, defaults to judgment evidence, moves workflow/full contract/roles into accessible tabs, distinguishes save-without-run from run-now consequences, and keeps the chosen detail tab across source reloads. Reply controls and compact-screen route navigation yield until the user explicitly revises; same-Agent READY still exposes only the original-host `/loopora-run` handoff, and repair states expose no commitment actions.
- Web conversation now distinguishes task-only, reviewed, and partial first turns. Matching Fit Review handoffs keep carried judgment collapsed, report known and missing counts, and remove duplicate examples; compact screens prioritize the task and start action before the first session, while route and history navigation return once conversation starts. Wrong-project and direct-path recovery remain separate instead of being silently applied.
- Creation choice now changes phase after Fit Guide handoff: a same-target review replaces the repeated “check fit” prompt, keeps the full task judgment in an expandable review, and puts route selection immediately after the handoff. Wrong-project drafts still keep the current target's fit entry visible, and clearing a draft restores the initial guidance.
- Fit Guide now preserves entered task judgment across every visible Web, creation-choice, and same-Agent continuation instead of only its inline draft buttons. Returning from creation choice restores the same-target review from browser-session storage, while a direct-path decision disables Web, setup, and expert creation exits consistently. Task judgment remains absent from URLs and server state.
- Live Run detail now hands active controls off deterministically when observation reaches a terminal state. Active-only actions are immediately hidden and disabled, and one explicit result-refresh action appears regardless of whether SSE or polling observed completion first; users no longer see a stale Stop control beside a terminal verdict.
- Cross-Run continuation now changes execution strategy instead of only carrying the last evidence gaps. A comparable target-level trajectory selects `continue_progress`, `change_approach`, `repair_regression`, `stabilize_mixed`, or `review_contract_change`; lifecycle retry and explicit advisory follow-up retain priority. The frozen mode and bounded delta enter every role prompt, Agent compact handoff, Run detail, `loopora loops status <run-id>`, and `GET /api/runs/<run-id>`. Evidence volume alone never selects a progress mode.
- Saved Loop reruns now preserve evidence continuity across CLI, Loop detail, and `POST /api/loops/<loop-id>/runs`. The latest unresolved terminal Run seeds the next Run with bounded evidence gaps; lifecycle failures seed retry context. First Runs and passing Runs start without inherited gaps, while user-recorded results remain closed unless an explicit advisory follow-up is requested.
- Loop detail, `loopora loops status <loop-id>`, and `GET /api/loops/<loop-id>` now share a `run_progress` projection across the latest two Runs. It compares stable coverage target IDs, reports improvements, regressions, closed/reopened gaps, and withholds direct progress claims for active Runs, lifecycle failures, missing legacy baselines, or changed target contracts. Extra evidence count alone never counts as progress.
- Saved Runs can now be exported from CLI (`loopora loops export-run <run-id>`) or Run detail as a curated evidence ZIP. The package carries the contract, iteration summary, evidence ledger, coverage, manifest, and task verdict; replaces local absolute paths; rejects unsafe symlinked sources; and omits workspace files, prompts, raw model output, provider transcripts, events, and logs. It is explicitly private task-review material, not a public-safe support bundle, project backup, full transcript, or independent task proof. CLI exports refuse to replace an existing file without `--force`.
- First-time evaluators can now run `loopora demo --open` before configuring an Agent or provider. Demo executes a real three-iteration Core workflow with bundled bilingual task contracts and a deterministic simulated executor, opens the completed evidence/verdict Run, uses only loopback Web and isolated temporary App/project state, labels simulated evidence globally, and deletes the entire demo state on Ctrl-C. It never reads or writes the normal Loopora App home, and its verdict is not real-task or provider proof.
- Agent plan/run/submit no longer start detached local Web processes while projecting preview links. They discover and reuse only a responding same-App-home instance; otherwise output stays relative and provides an explicit foreground `serve --open` command on an available port, keeping Ctrl-C as the visible lifecycle boundary.
- Agent Native run handoff now uses progressive disclosure. Managed compact run/next/submit output rebuilds a bounded first-step projection instead of leaking service-populated full summaries, while default plain output stops replaying the complete capability inventory and frozen strategy on every step. Exact role dispatch, coverage IDs, result/template paths, submit commands, full `--json`, and local run/step contracts remain available.
- Same-Agent `/loopora-plan` now keeps fit clarification, focused questions, working-agreement review, explicit confirmation, and candidate authoring in the current Codex, Claude Code, or OpenCode main session. Managed entries no longer start message-only alignment or a nested provider CLI as their first planning action; candidate validation begins only after confirmation, while message-only alignment remains an explicit non-interactive/Web fallback.
- Completed Fit Guide reviews now prepare one Agent message containing both `/loopora-plan` and the reviewed task judgment. CLI and Web distinguish “safe to save” from “ready to send”: Web continuation stays independent, while same-Agent setup/readiness comes before paste-ready handoff. No second message can detach the goal, fake-done risks, evidence, or tradeoffs from the command; without a completed review, the plain `/loopora-plan` fallback remains available and generic examples remain orientation-only.
- Same-Agent setup can now use `loopora init current --workdir "$PWD"` from Codex, Claude Code, or OpenCode. The command selects only a uniquely detected host, installs its project entry, runs the doctor readiness boundary, and reports `ready` only when `/loopora-plan` handoff is executable. It never prints session/thread identifier values and fails closed to explicit adapter commands when detection is missing or ambiguous; Same-Agent Web setup preselects the same host without installing on page load.
- Local Web first use now supports idempotent `loopora serve --open --workdir "$PWD"`. It starts foreground Web with Ctrl-C ownership when needed, but reuses a responding same-App-home service and exits after opening instead of creating a duplicate. Start, Fit, CLI Doctor, and Web Tools apply the same identity/auth and access-mode semantics: a matching running service remains on the requested origin, counts as ready, and is presented through one Doctor-owned open-existing action while the compatible `start_web` action kind remains stable. Adapter diagnostics reuse the same target-scoped Doctor readiness command instead of falling back to a default port, and redundant Web controls were removed. Plain `serve`, foreign App homes, non-Loopora occupants, and auth mismatches remain explicit port conflicts.
- `loopora dev release-plan` now prints a read-only maintainer release-readiness plan.
  It ties candidate version/tag, supported-status intent, default-fast/focused evidence, conditional journey checks, opt-in real probes, changelog notes, security support scope, package-build cleanup, and no-license package boundaries together.
  Real Probe workflow commands are bound to the release probe ref instead of the default branch, with `--probe-ref` available when the candidate version differs from the Git ref.
  Local release evidence commands preserve the release workdir so maintainers can copy them from the plan without accidentally collecting evidence from the caller's current directory.
  It does not approve or run a release.
  Blocked plans include rerun templates for unusable workdirs, missing candidates, or missing supported-status choices.
- Package metadata now links public package discovery to the changelog boundary, and the package-build gate verifies the required public project URLs alongside summary, keyword, identity, dependency, and no-license metadata.
- First-use routing now keeps task judgment ahead of setup without presenting it as executable too early: `loopora start` and `loopora fit` keep concrete Web/init/doctor commands preview-only until target and review prerequisites are ready, show independent Web continuation or same-Agent setup before the reviewed message, and expose a direct-path stop/record option before setup or creation.
- Quick Start docs distinguish wheel-backed adopter and editable contributor lifecycles from same-Agent project-entry cleanup, including how to refresh or remove the installed tool and why `loopora uninstall <agent>` only affects one project entry.

### Public Adoption Notes

- Support remains best-effort with no guaranteed response time; supported security scope follows [SECURITY.md](./SECURITY.md).
- Public diagnostic material should stay limited to the public issue support bundle, redacted `loopora doctor --public-json` output, `loopora --version` output, and `loopora version --json` output only when structured identity is requested.
- This repository currently does not declare a license; do not infer redistribution, reuse, or third-party intake rights from public repository access.

### Release Note Requirements

When maintainers prepare a release tag, move the relevant unreleased entries into a dated version section and include:

- Version or tag, release date, and whether maintainers mark the tag as supported under [SECURITY.md](./SECURITY.md).
- User-visible changes grouped by affected workflow or public contract.
- Compatibility, migration, rollback, support, security, or distribution risks that public adopters need before upgrading.
- Verification evidence: focused guide IDs, final `uv run loopora dev check` result, browser journey/review/probe evidence when relevant, skipped probes, residual risks, and package-build cleanup state.
- Private details that were intentionally omitted from public notes, described without secrets, exploit details, private paths, private logs, or sensitive run artifacts.
